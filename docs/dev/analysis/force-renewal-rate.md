# FRR：Force Renewal Rate（戦力更新力）

2026-11-21 利用者採用。通常プレイ画面に略語・数値を追加しない。内部評価・CPU判断・解析で使う。表示するならシステムメニュー内の解析情報まで。

中心となる考え方は、１全体ターンに前線の不完全ロボットを完全体へ差し替えられる件数。空きを作る速さ、生産件数、入荷数のいずれか１つだけをFRRとはしない。

## 計測上の区別

- **潜在FRR**：在庫・設備・経路・搬出入能力から推定する交換能力。推定条件と資源を何日維持できるかを併記する。
- **実績FRR**：実際に前線で成立した交換の件数／観測全体ターン数。欠損部品、汚損品、製造仕掛品、解体仕掛品を区別する。
- 国全体と必要な前線の局所値、初期・中盤・終盤、短期の交換と継続できる交換を分ける。
- 搬出と搬入が同時にあっただけで因果的な交換と断定しない。物理IDと後続用途を追い、対応未確認は別集計にする。

操作的な前線の定義、汚損の閾値、交換対応の取り方、計測窓は測定器の実装時に明示する。本書だけでは測定器やCPUのFRR評価は実装済みにならない。

## 解析する関係

FRRと、その後の地域獲得・地域喪失・地域純増、世界征服到達率、到達までの全体ターン数を追う。時間差を考え、勝利後の情報で過去を説明しない。初期領土・物量・資源・前線距離・SEED・趣向・ルール版を揃えて比較する。

400全体ターンで未決着の例は打切り・収束未判定。征服に400ターンかかった例として扱わない。

高FRRで地域純増が小さい場合は、更新地点が遠い、戦力の分散、守備損耗の補充、城壁・地形・敵兵力、攻撃判断、他方面での領土喪失との相殺を、具体的な記録から切り分ける。防衛維持や敵の拡大阻止に使われたFRRは無駄としない。相関を確認しても、直ちに因果や万能の勝ち筋としない。

既存の15分間隔のCPU・収束調査タスクへ、この解析方針を追記済み。計測の有効性を検証してからCPU判断へ段階的に採用し、趣向を画一化しない。

## FRR Errorの仮説

全地点のFRRを最大化するより、地点ごとの目標FRRへ適切に配分できる国が強い、という利用者の仮説。目標は当時の情報と作戦・予算から推定し、後の勝敗を見て逆算しない。

不足と過剰投資を別記録にし、戦略的重要度・地点数・実現可能な資源制約を考慮する。単純な誤差合計だけで国を順位付けしない。小さい誤差と後続の地域純増・到達率・所要ターンの関連を追い、過剰地点から不足地点へ配分を変えた同条件の候補でも検証する。この仮説と目標推定器は、まだ有効性未確認。

2026-11-21追記：符号付きFRR Error = 実際のFRR − 推定目標FRR。不足は負、過剰は正。まず現在の作戦の配分傾向（集中・分散、前線重視・後方重視、準備中・防衛維持）を分類する用途で検証する。正負の相殺で誤差ゼロになるため、国全体では不足量・過剰量・絶対誤差も併記する。作戦分類を勝敗の評価と混同せず、世界征服への予測力は別に調べる。

## 戦略カード候補の逆向き調査（相談案）
2026-11-21利用者案：世界征服直前から行動列をさかのぼり、有効そうな運用の類型を戦略カード候補にする。例「征服者の女の子パシリ：戦略」は製造重点地点と前線の間を往復し、ポケットで完全体を補給する運用。
調査では受取・運搬・前線搬入・補充・出撃や征服への後続を荷の系譜と時刻で追う。勝利直前に存在しただけの行動を勝因としない。同じ運用の未決着例、実行できなかった例も比較し、必要な地理・供給・容量・代替輸送の条件を残す。勝利後の逆向き説明は、当時の情報から推定するFRR目標や事前の勝敗予測とは別扱い。カードの実装、発動条件、所持者・自動化範囲は未確定。
