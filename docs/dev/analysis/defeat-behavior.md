# 敗退行為の調査とカード

征服が進んだかに加えて、CPUの計画が自陣営の勝利を目指しているかを調べる。判定の対象は個々の注文の損得より、その注文を選び続ける計画と目標設定。

| 観測 | 調べること |
| --- | --- |
| 戦力不足や強制された損失 | その時点で実行できた選択肢と、何もしなかった場合の損失 |
| 無理な計画 | 目標に必要な戦力・時間・輸送経路を用意できたか |
| 判断ミス | 守備数、損耗、工期などの見積もりを正すと同じ目標に沿う選択へ戻るか |
| 利敵に見える策略 | 一時的な譲歩で生き残る、共通の敵を抑えるなど、自陣営に期待できた利益 |
| オートバランサー | 世界や対戦全体の調整として明示された目標と、各CPU自身が最適化している目標 |
| 公開方針との食い違い | 実際の注文に至った目標・採点・例外が、説明書の記述と一致するか |

## コンピュータープレイヤーの取扱説明書

利用者に、CPUが何を目指し、何を好み、条件によってどの規則を優先するかを取扱説明書で公開する。素材の好み、撤退や廃棄の条件、同点時の選び方、オートバランサーの介入条件など、選択を変える規則も含める。説明書と実際の方針は同じ版に対応させる。

公開した方針に沿った選択は、そのCPUの個性や腕前として評価する。この定義では、負け越しや自陣営の損失だけを根拠に敗退行為カードを付けない。宣言と実際の注文が食い違えば、まず説明書と実装の不一致として扱う。公開された目標自体が勝利を妨げるなら、その目標をゲーム設計として見直す。

システムの検証ログには、実際にどの規則が適用されたかを残す。公開する判断規則と、進行中に相手から見える具体的な注文や作戦は別扱いとする。

- 注文を確定する前に、CPUが知っていた局面、適用した目標・優先順位・例外、実行可能だった候補と評価、選んだ注文を検証ログに残す。同点処理や乱数、計略で選択を強制された場合の理由も、選択を再現できるように記録する。
- 同じ状況で方針を再実行し、実際の注文が当時の方針から外れたかを照合する。外れていれば、実行時の制約や実装ミスで説明できるかを先に確認する。方針に沿っていても、方針自体が自陣営の敗北を優先している疑いがあれば、目標の設定を調べる。
- 弱いロボットを好むことや、奪われそうな機体を廃棄することは、選択時点の好みや戦術で説明できる。ビギナーとの比較は、説明書と実際の判断を詳しく照合する局面を見つけるために使う。

## ビギナーズプレイヤーとの比較案

ゲーム内の取扱説明書は全60キャラクターを表示する。共同攻撃の目標選び３種と、格納庫に守備を１機残すかどうかを組み合わせ、初期設定は６通りに10人ずつ割り当てた。編集はこの世界の同一キャラクター番号に適用される。趣向は、出撃可能と判断した候補の優先順に使う。

A〜Zのランクは、同一条件で十分な対戦成績が集まるまで未計測とする。ベンチの `--strategy-report` は勝者と参加者のキャラクター番号・差分番号を出力する。勝者の初期領地順位も合わせて確認し、キャラクター番号の割当と初期領地の有利さを入れ替えて検証する。

ビギナーは自陣営の勝利を目指し、手元と隣接地点の見える戦力だけで判断する固定方針とする。攻められる隣接地点を選び、攻めにくければ守備や補給に回る。読み違いや非効率が残る程度に単純化する。具体的な注文規則を固定し、結果を見てからビギナーの強さを変更しない。

同じ保存コピー・装備モード・ターン上限で、候補の方針とビギナー方針を同じ国にそれぞれ割り当て、他国の方針を固定する。別の国や独立したSEEDでも繰り返す。勝ち・負け・未決着を記録し、未決着を除いた勝率だけで評価しない。征服の勝敗を主指標とし、生存、独立維持、領地・戦力の変化は原因を追う補助指標にする。

ビギナーへの有意な負け越しは、方針や実装を点検する手がかりにする。同じ局面で選べた注文、適用された規則、その後の損失を照合する。目標や採点に原因がありそうなら、その規則だけを変えて同じ条件で再実行する。
