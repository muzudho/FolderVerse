# 軍用地点の集約と施設移転の評価

2026-11-25 利用者指定。目的は、時間が進むと軍用地点が減り、多地点を保有し続ける国が少なくなるかを調べること。施設移転件数の最大化や、奪われやすくすること自体は目的にしない。集約する国に、集中喪失のリスクに見合う世界征服への利点があるかを評価する。バックアップ付与などの新ルールは、現状測定の後の検討事項。

## 計測

- 固定DLL・同一初期保存から各全体ターンの軍用地点総数と直接所有国別の保有数を記録する。ルート陣営へ合算した数も別集計し、国と陣営を混同しない。
- 初期値、25・50・100・200・400ターンまたは征服到達時の分布、最大値、多地点保有の継続期間を比較する。「多い」の閾値は明記し、世界規模と初期保有数も併記する。
- 開戦での所有変更と、施設移転での無機能化を分離する。工場のみ移転は地点を残し、ランドマークも残るため、移転成功数を地点削減数と置き換えない。
- 合法な移転候補なし、CPUの候補生成から除外、既存予約との競合、予約後の不成立を区別する。安全な袋小路条件、中継用途、容量、経路、戦闘、手動管理を調べる。
- 移転後の輸送距離・混雑、製造と前線投入、地域獲得・喪失、集約先を奪われた損失と回復を追う。単なる容量増加を増兵や征服促進と同一視しない。

各試行は初期状態から累計400全体ターンまで。未到達は収束未判定とし、趣向に沿う長期化を直ちに不具合とはしない。同条件の介入比較なしに、地点数と征服速度の相関から因果を断定しない。

## 現行判断で確認した点

`ComputerFunctionTransfers` は通常の前線への集約に `EnclosedPocket` 条件を要求する。隣接する味方地点というだけでは候補にならず、入口を除いた側が安全に閉じている必要がある。格子状の海などで、合法な移転が候補生成に入らない可能性を調べる。既存の物流・部品操作等の予約がある地点も避ける。中継同士の全移転、工場だけの移転は別の判断経路である。

定期解析 `folderverse-cpu` に本項目を追加し、既存15分間隔を維持した。計測用ソースと結果はNAS `archives/convergence-analysis/functional-node-consolidation-2026-11-25/`。ゲーム本体の判断やルールは変更しない。
