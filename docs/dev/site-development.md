# 地点の増築と中継物流（2026-11-18）

利用者が採用したイメージボードに基づく。管理人を含む開発済みのTotalCapacityで外観を判定する。在庫数やWarehouseLimitではない。

| 用途 | グレードの境界 |
|---|---|
| 自由用途・採取・製造・城壁・詰所・港 | 0–9 / 10–19 / 20–30 |
| 中継 | 0–9 / 10–19 / 20–29 / 30–39 / 40–49 / 50–60 |

CubeNet.Developmentの共通ポリゴン形状を地星儀と展開図で使う。窓枠・扉・屋根の縁と継ぎ目・柱脚・荷箱・舗装を追加。形状は用途・段階・海陸別にキャッシュ。詰所は階層、城壁は横増築、中継は倉庫棟と荷さばき場が増える。港も桟橋を増やしクリック範囲へ反映。動的国旗は既存描画で屋根の高さへ追従。高山のオブジェクトなど既存の地形起伏を保つ。

新規世界の運否天賦完了時にRelayLogisticsEnabledを有効化する。通常の上限は30、中継は元の上限を保ち、中継→中継の全施設移転で加算（最大60）。基本１枠＋管理人ごとに通常４枠／中継７枠。管理人自身の占有を引いた純増は３／６。工場だけ外すと上限は増えず、管理人の効果だけ増える。工場を中継へは移せない。工場を除く中継同士の移転だけが中継を移転先にできる。予約プレビューもCPUの移転予約を反映する。

旧セーブのMaterials世界は旧容量を維持し、荷物を削らない。旧セーブへの新ルールの一括適用はしない。

初期用途は決定的な別乱数で多様化する。港の接続方向や大渦の条件は保持する。未採取資源がある地点を初期中継にして資源を閉じ込めず、採取用途にする。初期中継は工場０・自動管理であり、手動工場と混同しない。

CPUは隣接する中継を、工場等の接続が多い側へ集約する。余っている工場容量を稼働工場へ移し、資材のある安全な中継点を残す選択も行う。手動管理・進行中の輸送や部品操作・戦闘・容量・レーン上限は既存の予約可否で守る。これはまだ最適戦略の保証ではない。
