# 経番による朝順と昼夜景観

2026-11-21 利用者承認で実装。

- 全体ターンは１日。年・月・１年の日数は定義せず、加齢へ結び付けない。新聞の２桁日付は既存のまま。
- `WorldDayCycle` は既存の地理座標系と経番を使い、極を軸に側面４面の周長を一周として扱う。極の地域にも既存の経番を使用する。
- 自転方向は世界SEEDから固定的に決まり、偶数は正方向、奇数は逆方向。同じSEEDでは同じ方向。星抽選の軌道模型の自転もこの方向へ合わせる。
- 人間の内政受付順は、征服者本人の現在地域へ朝が来る順。同経番は全体ターンごとにエントリー番号の優先を循環する。移動予約先は参照しない。
- CPUの操作表示と、物流・取引・施設移転・計略・進撃の国別判断順も朝順を用いる。既存の人間受付／CPU一括計画という段階構成は維持しており、人間とCPUを１本の交互受付へ変更したものではない。
- 全員の内政受付後に従来の配送・開戦を実行する。容量・コスト・能力・勝利条件は変えない。翌日の人間受付はその時点の居場所で最初の担当を選ぶ。

## 景観

内政の地星儀は表示中の征服者の経番を朝８時の基準にする。星抽選の近景は90秒で一周する景観時計。年や公転周期の定義ではない。

昼は10〜18時を通常色、朝6〜10時と夕方18〜22時を滑らかに補間。８〜20時の半周が昼の中心領域になる。朝は紫、夕方は赤を混ぜ、夜は青みを残して暗くする。極の地表は地域の既存経番に対応する。

地形頂点の色だけを変えるので、元地形・資源・ルート・当たり判定は変えない。国旗と案内表示は暗くしない。内政の建物は夜色になり、小さな暖色の窓を表示する。投影影・太陽遮蔽・日照による生産補正はない。展開図は図としての従来表示を維持する。

元の頂点と経度を保持し、朝の基準が変わった時だけ頂点色を更新する。毎フレーム地形を再生成しない。地形の再生成時には昼夜キャッシュを破棄する。

## 検証

５SEEDの左右自転・人間受付順・保存復元・全地域の位相範囲・側面の描画経度との一致、４人の実内政と途中保存後の次担当、全員の受付完了まで配送を保留することを確認。４時刻の地星儀を実描画し、昼夜差と建物の灯りを目視確認。初回に前後面の符号が逆だったため一致検証で検出して修正。
