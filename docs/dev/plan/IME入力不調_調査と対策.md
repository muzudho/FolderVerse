# ゲーム終了後のIME入力不調：調査と対策

確認日：2026-10-07

## 症状と調査

- ユーザー報告：ゲームを終了した後、Visual Studio 2026のエディターで日本語入力ができなくなる。
- ゲームのソースには、IMEのON／OFFや入力言語を変更する処理はなかった。
- 現在の依存関係はMonoGame.Framework.DesktopGL 3.8.5.1、MonoGame.Library.SDL 2.32.10.2。
- SDL2は標準でネイティブIMEのUIを抑制する。[SDL公式の設定説明](https://wiki.libsdl.org/SDL2/SDL_HINT_IME_SHOW_UI)。
- 使用版に対応する[SDL2のWindowsキーボード処理](https://github.com/libsdl-org/SDL/blob/release-2.32.10/src/video/windows/SDL_windowskeyboard.c)では、IME初期化時にこの設定が無効だと `UILess_SetupSinks` を呼び、WindowsのTSFへ接続する。有効ならその経路を使わない。
- この連携を原因候補として扱う。Visual Studioでの症状を再現できたわけではなく、IMEのOFF状態と候補表示の抑制も未判別。

## 実装した対策

- [x] `Game1` の静的コンストラクターで、Windowsの場合だけ `SDL_IME_SHOW_UI=1` をプロセス環境へ設定。MonoGameの基底コンストラクターがSDLを初期化する前に適用する。
- [x] Windows標準のIME表示を利用し、SDL2のUIなしTSF連携を避ける。
- [x] Windowsの永続設定、Visual Studio、他のアプリのIME状態を変更しない。
- [x] `tests/ImeUi` で、事前値0からゲーム生成後の実際の `SDL_GetHint` が1になることと、通常起動・実行・破棄を確認。
- [ ] Visual Studio 2026から実際に起動・終了した後の日本語入力復帰を確認。デバッガーによる強制停止も別途確認する。

## 実環境での確認手順

1. Visual Studioのエディターで日本語を入力できる状態にする。
2. 修正後のゲームをF5で起動し、ウィンドウを閉じて通常終了する。
3. 同じエディターへ戻り、日本語の変換と確定を確認する。
4. ゲーム実行中にAlt＋Tabで戻る場合、およびデバッガーの停止ボタンで終了する場合も確認する。
5. 症状が残る場合は、タスクバーのIME表示が「A」か「あ」か、半角／全角で切り替わるか、他アプリでも入力できないかを記録する。候補UIの不調と入力モードの変化を切り分けて次の対策を決める。

## ユーザー確認後の再調査

- ユーザーから「直っていない」と報告あり。`SDL_IME_SHOW_UI=1` の変更だけでは症状は解消していない。原因は未特定。
- [x] 起動前、ゲーム生成後、アクティブ／非アクティブ化、終了要求、SDLを含めたゲーム破棄後に、前面アプリのIME診断を操作ログの `ime_state` として記録。
- 診断は `WindowsImeDiagnostics.cs`。前面ウィンドウと入力フォーカス、プロセス／スレッドID、キーボード配列、IMEの報告する開閉・変換・文モードを読み取る。応答待ちは各取得50msを上限とする。値が取得不能ならnull。現代のTSF IMEではこれらの値だけで入力可否を断定しない。
- ログをSDL破棄後まで開いておくため、操作ログの破棄を `UnloadContent` から `Dispose` の終了処理へ移動。`ImeUi` で破棄前後のログ項目、`OperationUi` で既存の記録動作を検証済み。
- [ ] IME表示がA／あのどちらか、半角／全角で復旧するか、ウィンドウを閉じた通常終了／デバッガーによる強制停止のどちらで起きるか、ユーザーの追加情報を確認する。
- [ ] 修正後の起動・再現時の `Logs/operations_*.jsonl` の `ime_state` を比較して、次の対策を決める。

入力状態を推測してVisual StudioのIMEを強制変更する処理は追加していない。現時点では未解決・診断追加済み。

### 追加情報と診断対象の修正

- ユーザー確認：Visual Studioは「A」、ほかのウィンドウは「あ」。半角／全角で戻せるか、終了方法の違いはまだ未確認。Windows全体で日本語入力が不能になっているとは断定しない。
- 直近のユーザープレイログ `operations_20261007_155347_866_216335d9.jsonl` では、起動前と終了後の前面プロセスはコマンド画面で、開閉の報告値は両方0、配列・変換・文モードも同じだった。このログにVisual Studioの状態は含まれていないため、VSの不調の原因を説明する証拠にはならない。
- `ime_state` に `visualStudio` を追加し、`devenv` のウィンドウとフォーカスの状態も同時に読む。取得できない場合も記録し、推測したON／OFFで上書きしない。ゲームを起動する前面ウィンドウがコマンド画面でも、VSの前後比較を可能にする。
- 実環境での再現と修復確認は引き続き未完了。
