# CPUによる計略カードの利用

内政確定時に用途計画後・物流と施設移転前に、各陣営の根が実行可能な計略を１枚まで選択する。対象は現在実装済みの城壁越しの出撃・城壁への救援・多地点からの集中攻撃。候補生成と予約・確定は人間と同じパターン定義を共有し、CPU専用の陣営権限で呼ぶ。人間のLeader値や操作権は変更しない。

守備を残す趣向と攻撃優先方針で救援/攻撃を比較し、攻撃は既存と同じ守備見積り＋余力を要求する。最近失敗した同数以下の出撃、手動管理地点、進行中の部品編集/直送/長距離配送を避ける。確定地点は同じ内政中の物流/施設移転から保護する。世界征服への効果は使用件数と独立に測る。

各陣営・各ターンのStratagemDecisionsに候補数、種類別件数、見送り理由、選択種類・対象・使用地点・予約/確定を保存。Headlessのstratagem行とStatisticsのstratagemsにも記録する。manual_controlは人間操作保護、no_candidatesは物理候補無し、existing_operationは既存操作競合、insufficient_forceは兵力不足、recent_failed_attackは失敗反復保護、lower_priorityは他候補を選択したこと。候補生成段階で除外された個別地点の理由数までは記録しない。

重要な訂正: 23:23監査のFind(world,0..19)は人間操作用ControlledParty経由で、ComputerOnlyでは空になる。従って当時の初期0/停止400の候補0という値は物理機会ゼロの証拠に使用しない。CPUから選択経路が未接続だったというソース上の診断は有効。以降はFindComputerで監査する。

検証: 既存人間計略回帰に加え、0人間Leader=-1でも候補発見・３種類それぞれの予約/保存/確定、Leader不変、１陣営１回、決定記録の保存、Reset消去、人間操作保護を通過。最初のCPU fixtureは手動工場設定を引き継いでおり正当に拒否されたので、自動設定に揃えて再実施した。ゲームルールや戦訓の未学習挙動は変更しない。
