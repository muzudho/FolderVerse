まずGitHub ReleasesでWindows向け無料の試遊版を公開する案、良いと思うぜ（＾▽＾）
おすすめは「GitHubで開発・配布 → itch.ioで遊ぶ人への入口を作る → 手応えを見てSteam → Switchを検討」という順番だぜ。

| 公開先 | フォルダーバースでの役割 |
|---|---|
| GitHub Releases | 無料版の配布、バージョン管理、不具合報告 |
| itch.io | スクリーンショットや遊び方を見せるゲーム紹介ページ |
| Steam | 更新・導入の手軽さや実績などを備えた販売版 |
| Switch | コントローラー操作や画面配置を整えた移植版 |

GitHub Releasesには実行ファイルなどの配布物を添付できる。自動で付く「Source code.zip」とは別に、遊べるZIPを用意するのが大事だぜ。
[GitHub公式説明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)  

最初の公開は、こんな形が扱いやすいと思うぜ。

* バージョンは v0.1.0、GitHubでは Pre-release にする。
* FolderVerse-v0.1.0-win-x64.zip を添付する。
* ZIPを展開して起動できる形を目指し、.NETランタイムを同梱する。
* 短い起動説明、操作方法、既知の不具合、セーブの保存先を添える。
* 開発環境のない別PCで、ダウンロードから起動・セーブ・再開まで確認する。
* READMEの「配布版はまだありません」をダウンロード案内へ更新する。

今のプロジェクトは .NET 9／MonoGame DesktopGL なので、まずWindows版に絞るのが自然だぜ。配布用には開発フォルダーを丸ごと詰めず、必要な実行ファイル・素材だけを収めよう。

公開前に１つ整理したいのが、コードと画像・音楽のライセンス範囲だぜ。現在の [LICENSE.txt](D:/github.com/muzudho/FolderVerse/LICENSE.txt) はMITだけど、著作権表示が [year] [fullname] のままになっている。

オープンソースと有料販売は両立する。ただし、オープンソースのコードは第三者による商用利用も認めるものだぜ。
[OSI公式FAQ](https://opensource.org/faq)  

将来の販売も考えるなら、例えば「コードはMIT、キャラクター画像・音楽・ロゴは別の利用条件」と範囲を明記する案がある。外部ライブラリーやフォントの必要な表記も、配布物にまとめておくといいぜ。

itch.ioは、ゲーム紹介と無料ダウンロードの入口として相性が良さそうだぜ。最低価格を０にして、任意の支援を受け付ける設定もある。
[itch.io公式説明](https://itch.io/docs/creators/pricing)  

Steamはその次でいいと思うぜ。現在は１作品につき Steam Direct登録料100米ドルが必要になる。Steam公式案内
無料版を残して販売するなら、「Steamで管理できる便利さ」「実績」「追加キャンペーン」など、購入する理由を分かりやすく示したい。生成AIの画像などを製品に使っている場合は、Steamのコンテンツ調査への申告も準備する必要があるぜ。
[Steam公式説明](https://partner.steamgames.com/doc/gettingstarted/contentsurvey?l=english)  

Switchは、MonoGameに対応経路がある。ただし任天堂の開発者登録・Switch向けアクセス申請と、MonoGame側のコンソールアクセス手続きが必要だぜ。今のWindows版をそのまま出す感覚ではなく、操作・文字サイズ・性能も含めた移植として考えよう。
[任天堂の登録案内](https://developer.nintendo.com/register)、[MonoGame公式案内](https://docs.monogame.net/articles/console_access.html)
