# ロボット輸送　＞　世界観設定


## 玩具の兵隊ロボット

１体のロボット（［隊長］と［兵］）は以下の３つのパーツで構成される。  

* 頭部（センサー、カメラ、マイクなどの情報収集装置）
* 胴体（CPU、メモリ、バッテリーなどの制御装置）
* 脚部（モーター、アクチュエーターなどの移動装置）

ロボットは、以下の７つの状態がある。  

* （１）［脚］の１つのパーツが揃っているロボット
* （２）［胴］の１つのパーツが揃っているロボット
* （３）［胴・脚］の２つのパーツが揃っているロボット
* （４）［頭］の１つのパーツが揃っているロボット
* （５）［頭・脚］の２つのパーツが揃っているロボット
* （６）［頭・胴］の２つのパーツが揃っているロボット
* （７）［頭・胴・脚］の３つのパーツが揃っているロボット

戦闘に参加できるのは、［頭・胴・脚］の３つのパーツが揃っているロボットだけである。  

以下のような組み合わせのロボットは存在しない。  

例： ［頭・頭・胴］、［脚・脚］ etc...


## 節点（Node）

［節点］には、ロボットのパーツを製造する［製造工場］が最大１つある。  
また［節点］は、ロボットを移送する［輸送路］でもある。  
この［節点］には同時に１２体のロボットしか置けない。これを［容量］（Capacity）と呼ぶ。  

画面上の１つの［節点］に、最大１２体のロボットが居る様子が映されることを想定している。  
［在野］のロボットは、画面上に表示されない。（調べれば見ることはできる）  

ロボットは、征服者の色で塗られている。  
［手下］などの関係性により、１つの［節点］に、複数の征服者のロボットが混在することもある。  
［捕獲］しているロボット（捕虜）もあるかもしれない。  

［製造工場］には７種類あり、どのパーツが揃っているロボットを作れるか、違いがある。  
１体のロボットを作るには、容量が１つ空いている必要がある。  

［組み立て］や［分解］は、どの［節点］でも行える。  
例えば、［頭］と［胴］と［脚］のロボットに、容量３つ割くのはもったいない。  
［頭・胴・脚］のロボットに組み立てることで、容量の消費を１つにできる。  

［頭・胴・脚］のロボットを［頭・脚］と［胴］のロボットに分解することもできる。この場合、容量の消費は１から２へ増える。  


## 輸送計画（Transport Plan）

１つの［節点］につき、２０人の征服者が、それぞれ別に［輸送計画］を設定できる。  
自分のロボット（７種類）について、次はどの［節点］に移送するかを確率的に決めるものだ。  
５％ずつ、２０分率で割り振る。  
［頭・脚］のロボットがいるとき、  
まず［頭・脚］プランが優先され、容量の問題でそれが実現できないとき、［頭］、［脚］と下位のプランに従う。  
優先順は、頭４点、胴２点、脚１点として、累計して大きい方を優先する。  

こちらに［頭・脚］ロボットがあり、［輸送先］に［胴・脚］ロボットがあり、［頭］だけを輸送するのが都合のよい場合、  
［頭］だけを［輸送］するといったプランを事前に立てておくこともできる。  


## 輸送の衝突

輸送先に１体しか置けず、２つの［節点］から同時に輸送が行われた場合、衝突が起こる。  
どちらを優先するかも、［輸送計画］に書いておけると良さそう。  
［受け入れ計画］として、どの［節点］を優先するか設定しておく。  


## 画面上

１つの［節点］に、最大１２体のロボットが居る様子が映される。  
［内政フェーズ］終了時に、ロボットの移動（輸送）が映される。  
衝突が起こった場合は、（輸送）は実現されない。（ロールバック）
