# 地点の機能移転

更新：2026-11-04。

## 操作と実施時期

内政フェーズの地点インスペクター［地点庁舎］（海では［地点監督船］）に［地点の機能移転の予約］を置く。隣接する、自国または操作できる配下の友好地点を一覧か地図から選ぶ。予約後は行き先と［予約取消］を表示する。

全員の内政終了後、配送フェーズの最初に移転を実施する。その後、移転後の拠点を使って直送便・長期輸送を処理し、軍事へ進む。移転で全体ターン・産業ターンを追加しない。

移転先が無機能地点なら引っ越し、有機能地点なら機能を集約する。同じ配送で複数の移転元から一つの先へまとめられる。移転先をさらに別へ移す連鎖や循環予約は認めない。移転元・移転先・辺が継戦中、または出兵中ロボットの帰還枠がある場合は予約できない。実施前に所有国や経路の条件が崩れた場合は移転せず、失敗結果を残す。

## 有機能地点と無機能地点

全地点は初期状態で有機能。移転すると元地点の機能単位が０になり、移転先へ加算される。元地点のID・表面領域・領有情報は消さず、集積先のIDを参照先として保存する。集積先を再移転すると、配下の参照元も新しい集積先へ付け替える。

無機能地点は通常の地点インスペクターと管理用フォルダーツリーの操作対象から外す。ただし移転先選択には残し、そこへ機能を戻せる。地図では小さい円にし、クリックの当たり判定は従来の大きさを保つ。ホバーには無機能であることと操作先を表示する。

`NodeFunctionTransfers.Members`から集積先と元地点の範囲を取得できる。これは将来の同時征服判定に使える元情報であり、現時点では集積先の陥落によって参照元の領有も一括変更する新ルールは追加していない。

## 工場・格納庫・参照元

格納庫の容量と在庫、常設・作業員レーン、選択中の製造品、工期・進捗・休憩、進行中の廃棄レーンと対象を引き継ぐ。格納庫容量は各地点12枠の合計。常設レーンと作業員レーンの上限も合計し、保存後の工場再設定で削らない。空き枠確保数も合算する。

工場は３レーン、格納庫と直送便の各側は12区画ずつのページで表示する。工場とロボットには元地点の情報を残す。地図上のロボットは、自分の参照元が同じ集積先に属し、友好領内にある限り元地点に表示できる。戦闘や配送で別拠点へ移った場合はその拠点に表示する。ロボットのクリックから開く操作先は集積先。

直送便、手動組立の予約、出兵元、長期輸送指示も移転先へ付け替える。長期輸送指示の進捗・回数を残し、併合で合計比率が360度を超える場合は縮小する。移転で同じ拠点内に吸収された仮到着先への直送便は取り消し、運ぶ実物は失わない。

## 配送経路

配送は有機能地点間で行い、途中の無機能地点は１配送フェーズでいくつでも通過できる。有機能地点へ到達したらその区間を終え、同じ配送中にさらに別の有機能地点へ中継しない。敵領の無機能地点、継戦中の地点・辺は通さない。

軍事の出兵経路はこの配送経路とは別で、既存の地点間移動のルールを維持する。

## 保存と検証

機能単位、参照元・集積先、予約、拡張容量、製造レーンと廃棄設備を保存する。旧セーブは全地点を有機能・12枠・移転予約なしとして読む。

`tests/FunctionTransfer`で予約時期、引っ越し・満杯同士の併合、複数元の集積、参照表示とグループ範囲、複数の無機能地点を通る一度配送、長期計画の付替え、敵国化の失敗、旧保存移行を確認する。`--ui`で予約ボタン・移転先選択・配送時実行・工場／格納庫／直送便の２ページ目を描画する。
