# AIエージェントの引き継ぎ

## Demo のクリック位置点検と修正

利用者の依頼（2026-11-01更新）により、終日30分ごとに点検回と修正回を交互に定期実行する。予定は日本時間で毎時00分に点検、毎時30分に修正。先行する点検・修正が実行中の場合は重複実行せず、次の定期回へ送る。実際の有効状態はアプリの定期タスク設定を参照する。

- 点検回：ゲームコードを変更せず、[点検記録](demo-click-audit.md)に再現できた問題と未確認箇所を書く。
- 修正回：点検済みの未解決項目を再現して修正し、[修正記録](demo-click-fixes.md)へ変更・検証結果を書く。点検記録の状態も更新する。

最初にリポジトリのAGENTS.md、現在のGit差分、本書と両記録を確認する。利用者の変更や起動中ゲームを上書き・停止しない。コミット・プッシュ・公開は行わない。

### 点検する内容

主な入口は `FolderVerse/Game1.Demo.cs`、`FolderVerse/Game1.DemoDomestic.cs`、`tests/DemoUi`、`tests/DemoInspectorUi`。内政のプライマリーボタン、直送便モードの退避・復帰、左右インスペクター、地図切替、格納庫や工場、閉じる操作を優先する。その後、残りのDemo経路を巡回する。

指示のカーソル位置・クリック先・クリック後の実際の状態を照合する。画面にマーカーを描くだけのDemo操作も対象とし、状態を直接変更できたことだけでクリックが正しいとは判定しない。解像度、画面拡縮、地図の向き、アニメーション待ち時間も確認する。全経路を確認できなければ実施範囲と次回の続き位置を明記する。

各問題には `DEMO-0001` 形式の連番を付け、対象ファイル・Demo段階・再現手順・期待結果・実際の結果・確認時刻（JST）・HEAD・関係する未コミット差分・解像度・証拠を残す。同じ問題を重複登録しない。状態は「未解決」「修正中」「検証待ち」「完了」「要再確認」で管理する。実行不能や未確認は正常扱いしない。

### 修正と検証

修正前に現在のコードでも再現するか確認する。可能なら描画・入力と同じボタン矩形からDemoのクリック位置を求め、固定座標の再調整を繰り返さずに済む形にする。Demoに合わせるためだけにゲームのUI仕様を変えない。関連テストと実描画・Demo遷移を確認し、実施したコマンドと結果を記録する。ビルド成功だけで完了にはしない。再現できない既報は理由付きの「要再確認」とする。

既存のビルド出力を優先して利用し、出力先の増殖を避ける。実行中のゲームと競合する場合は既存の検証用出力先等へ分離する。素材生成や復元で失敗した場合は、その制約と未実施範囲を記録する。

### Nortonによる起動待ち（2026-11-03利用者申告）

このPCではNortonが検証用プログラムの起動を30秒～１分程度保留する場合がある。起動直後の無出力だけでは、Demoの停止やクリック不具合と判定しない。

- ビルドと各テスト実行を分け、起動要求時刻、対象DLL／EXE、プロセスIDが得られればそのID、最初のログ時刻・終了コードを記録する。テスト側のSeed表示など、実行開始のログとゲーム内の進行ログを区別する。
- 起動確認は10～15秒程度の短いポーリングで行い、最大120秒の猶予を取る。ツールの「実行中」返却や無出力を失敗と扱わない。長時間の一括sleepを避け、利用者からの入力を受けられるようにする。
- 120秒を過ぎても開始を確認できない場合は「環境による起動待ち／実行未確認」とする。Nortonが原因かは、利用者の申告だけで個々の実行の確定原因にしない。画面やログ等で確認できた場合だけ、その証拠も残す。
- 同じ検証プロセスが残っている間は重複起動しない。終了と競合なしを確認できた場合のみ、短い間隔で状態を確認しながら30～60秒待って１回だけ再試行する。解消しなければ未実施範囲と続き位置を記録して次回へ送る。再試行成功だけでゲームコードの修正完了にはしない。
- Nortonの無効化、除外設定の追加、隔離からの復元、権限の変更はこの定期タスクでは行わない。利用者のゲームを終了しない。実行開始後のゲーム内で繰り返す同じ段階・例外は起動待ちと混同せず、Seed・入力・描画と合わせて通常どおり調査する。

### 引き継ぎと重複実行

点検回は記録末尾に開始・終了時刻と「完了／中断」を残す。修正回は完了した点検結果を対象にする。同じ対象の別実行や利用者の編集中の変更と競合するときは変更せず次回へ送る。時間が空いたことだけで前の実行が終了したとみなさない。

2026-10-31に初回点検と修正を実施した。現在の確認済み項目と未確認範囲は点検記録、修正と検証結果は修正記録を参照する。利用者の報告だけで、未検証の項目を確認済みの不具合として登録しない。
