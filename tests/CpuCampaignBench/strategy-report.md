# 初期条件と駆け引きの比較

同じ保存コピー、モデルDLL、ベンチDLL、ターン上限で対照と介入を実行する。元セーブと公開版は読み取り元に使い、出力はNASの検証先へ分ける。

```powershell
dotnet CpuCampaignBench.dll $inputCopy 75 $controlSave --strategy-report > $controlLog
dotnet CpuCampaignBench.dll $inputCopy 75 $trialSave --strategy-report --hold-against=1:19:0 > $trialLog
```

`--hold-against` は「コピー開始からの手数:行動する国:相手の国」。国は内部IDで０始まり。指定した手だけ、その国が相手の陣営へ出した敵対進軍を見送る。出撃先は対照の `order` と `targetOwner` から選ぶ。便や攻撃を作り足す既存の診断オプションも使える。上の相手IDは書式例。

- `strategy-initial` に全陣営の順位・地域・地点・完成体・装備・製造レーン、SEED、装備モード、表示Leader、各ファイルのハッシュを記録する。地域数が同数の首位は全員を記録する。開始ターンが０の比較は初期配置の比較に使える。
- `strategy-turn` に各ターンの順位、順位を落とした陣営、独立陣営から外れた国、前ターンに地域数が少なく当ターンに厳密に多くなった追い抜きを記録する。途中で同数になった追い抜きは順位の履歴から確認できる。
- `strategy-hold` に実際に見送った注文を記録する。対象０件なら介入は成立していない。`logistics`、`order`、`battle`、`relations` を同じ手数で照合すると、その後の出撃先・戦果・陣営変化を追える。
- `strategy-summary` に勝者の初期順位、初期地域首位だったか、首位集合の変化回数を記録する。上限で未決着なら勝者は空欄。両実行の経過比較には共通のターンを使う。

順位の変動だけでは、どの判断が効いたかは分からない。対照と介入で、介入前の順位と注文が一致し、介入後に相手の注文・戦果・順位のどこから分かれたかを見る。初期首位や装備が勝率を予測するかは、複数の独立したSEEDで初期条件ごとの勝敗を数える。同じ世界の介入実行は独立したSEEDとして集計しない。
