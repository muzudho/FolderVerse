# キャンペーン#1・#2と共通キャラクター選択

`dotnet run --project tests/CampaignDuel`

24種類の乱数設定で、1×1×1、人間1人＋CPU1人、両国の連続した3地域、同キャラ、通常の地点・ロボット初期化、保存復元を検証する。

実際のGame1でスタートメニュー、モブの案内、60人の一覧、両者で60人目を選択、個別ランダム、戻る、540pのクリック、ゲーム開始、専用テスト用オートセーブと「続きから」を確認する。利用者の保存先は使用しない。

キャンペーン#2「三国誌」は2×2×2、人間1人＋CPU2人。24種類の乱数で、各国が隣接する2面全体（8 sectors）を所有し、全24 sectorsに空白・重複がなく、選択キャラクターと保存復元が一致することを検証する。地形・地点性能・ロボット等は通常のランダム初期化を使う。

両キャンペーンは同じ選択画面を使う。左は参加者を6人ずつ、右はキャラクターをページ表示し、それぞれ独立してページ送りする。初期の仕切りは中央。仕切りをドラッグすると左右の幅と候補一覧の列数が変わる（参加者側は画面幅の約33〜61％）。60人目の参加者の選択、60人目のキャラクターの選択、540pでの仕切りドラッグ、両シナリオの開始を実入力で確認する。
