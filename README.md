# Folder Verse

MonoGame製のゲーム試作。Visual Studioで `FolderVerse.slnx` を開いて実行する。

Windows版はSDL初期化前に、このプロセスだけ `SDL_IME_SHOW_UI=1` を設定して標準のIME表示を使う。SDL2のUIを隠すIME連携を避け、ゲーム終了後に日本語入力ができなくなる症状への対策とする。WindowsやVisual StudioのIMEを強制ON／OFFにする処理は行わない。`tests/ImeUi` で実際のSDLの設定値と起動・終了を検証できるが、Visual Studioでの日本語入力復帰は実環境で確認する必要がある。

この設定変更だけでは症状が解消しないとの報告があり、IME問題は調査中。起動前・フォーカス切替・終了・ゲーム破棄後の前面アプリのIME状態を操作ログの `ime_state` に記録する。[調査状況](docs/dev/plan/IME入力不調_調査と対策.md)を参照。

## 兵隊ロボット・輸送・自動戦闘

通常ゲームはロボット個体で戦う。人口の戦闘員数とは独立しており、領有節点には初期状態で完成体３体と製造工場がある。節点の配備は所有者を問わず合計12体、征服者の直属枠は別に12体。頭・胴・脚の７種類の組み合わせを管理し、完成体だけが戦場へ入る。

［メニュー］→［ロボット輸送計画］で、自国の節点と自分の配備を調査・編集する。左右ボタンで節点を選び、自分のロボットのカードを選択する。［組み立て］は同所有者の重複しないパーツをまとめ、［選択部分へ分解］は下の７種類のボタンで選んだ部分へ分ける。どちらも次の全体ターンで予約を実行する。

地図ではロボットのいる節点の上に、１体につき１本のピンを表示する。縮小時と地球儀は２・３・２・３・２本の段をずらした最大12本の並びで、頭＝丸、胴＝縦棒、脚＝横の台座の有無から７構成を識別できる。各ピンは個体の所有国の色になる。展開図をホイールで拡大すると、４列×３段の12枠のロボット表示へ切り替わる。地図上の配備表示は数字に置き換えない。最大64倍まで拡大可能で、地図ビューの中心を固定したまま拡縮する。スペース＋ドラッグで地図を移動する。節点やピン表示へマウスを置くと詳細を調査できる。混雑時は表示の重なりを避けるため一部を間引くので、目的の節点へ拡大する。直属枠は地図の配備に含めない。

製造品と工期を変更でき、製造停止で工期を遅らせられる。工期満了で満杯なら１体だけ出荷待ちとなり、空けば出荷して次の工期を0から始める。初期の征服者所在節点には廃棄炉もある。［廃棄］フラグ付きの個体を、空いたレーンへ自動で１体ずつ入れる。処理時間は頭１・胴２・脚２全体ターンの合計で、完成体は５ターン。時間の設定や手動の廃棄予約は撤去した。

輸送計画は自分のロボットの７種類ごとに５％ずつ設定する。未割当率は留まる選択。［受入１位］で、表示した隣接節点からの受け入れを最優先にする。部分輸送と到着時の直接合体、満杯同士の交換に対応し、不成立便は分解・合体も含めて巻き戻す。全体ターンの順序は、廃棄完了→組立・分解予約→輸送・到着合体→製造出荷。確定した輸送だけを再生する。

［移動］では同行する完成体を１体ずつ、または［全員］で選ぶ。直属の完成体と征服者も同行する。［ポケット］では自分の直属ロボット12枠を調査でき、現在地の節点とロボットを出し入れできる。ポケットは通常の輸送計画から独立している。

戦闘は10×10盤面で全軍が同時に動く自動観戦。短剣３回・小銃３回・盾４回を持ち、行動選択→配置→巻き戻し→攻撃→被攻撃→消費→転倒の順で解決する。旗更新→増援→戦意・勝敗が続く。観戦画面で再生・一時停止・１フェーズずつ前後・結果まで進むを操作できる。駒への指示はできない。

戦場の再生が終わると５秒のタイマーバーと一時停止ボタンが現れる。停止しなければバーが伸び、５秒後に次の戦場へ進む。最後の戦場なら世界へ戻る。停止中は残り時間を保持し、再開で続く。手動で次へ進むこともでき、観戦終了で全体ターンは増えない。メイン画面の下部は［ポケット］［ロボット輸送計画］［移動］［次のターン］の４ボタン。［ロボット輸送計画］から節点の配備・輸送計画へ入れる。製造設定は節点ダイアログ下部の［ロボット製造工場］から開く。

１戦場は最大４国、５国以上は分割野戦後に生存軍が合流する。野戦・壁のある陣戦・船と橋の海戦を用意している。無戦意10戦闘ターン、継戦の区切り100戦闘ターン、説得の距離４・確率５％は調整用の暫定値。継戦は位置・装備・旗・待機兵・乱数・戦意をメモリで保持し、次の全体ターンに続く。継戦中節点の内政と継戦辺の通り抜けは止まる。工場画面で隣接する継戦を選び、完成体を増援へ送れる。

[実装計画・進捗・暫定仕様](docs/dev/plan/ロボット輸送と戦闘_段階的実装計画.md)を参照。新規検証は `tests/RobotTransport`、`tests/BattleRules`、`tests/RobotCampaign`、`tests/RobotUi`。`dotnet run --project tests/RobotUi/RobotUi.csproj` などで実行できる。旧人数相殺は既存回帰テスト用に `Campaign.UseRobotCombat=false` とした場合にだけ使い、通常の操作画面からは切り替えない。

## 画面の流れ

地図の［現在地へ移動］は、征服者が現在いる節点をビュー中央へ表示する。展開図では倍率を保って現在地の面へ切り替え、位置を中央に寄せる。地球儀では現在の節点が正面中央になるよう回転する。

1. START → 世界作成。寸法は1～5。STOPで固定、左ドラッグで回転。
   寸法のうち2軸が1より大きい世界の名称は「地盤」。
2. 世界確定 → 世界征服者作成。7×5グリッドの外周20マスに人物、中央15マスに世界を表示。
3. 人物のSTOP → 人物確定 → 初期配置の抽選。
4. 配置のSTOP → 国境線と首都の旗を確認 → 初期配置確定 → 世界征服者選択。
5. 顔をクリックして操作する人物を確定。選び直しや配置の確認もできる。

## SEEDの再入力

画面下のSEEDボタンをクリックすると、ゲーム内の電卓風ダイアログが開く。Windows Formsは使用しない。
数字ボタンまたは物理キーボードで入力する。Cは全消去、<は1文字削除、Enterは適用、Escapeはキャンセル。
範囲は0～2147483647。ダイアログ表示中は抽選を停止する。

- 世界SEED：寸法と海・陸の形を再現する。
- 人物SEED：60人×6枚の完成画像から選ぶ20人と国の色を再現する。
- 配置SEED：確定した世界と人物に対して、領地と首都を再現する。

完全に同じ初期状態を再現するには、3種類のSEEDを控え、世界→人物→配置の順に入力する。
人物を変更すると、依存する初期配置をリセットする。
世界の表面セル数は `2 × (Width × Height + Height × Depth + Depth × Width)`。3×3×3なら54。
セル数が20未満の場合、外周には20人全員を表示し、先頭のセル数ぶんが参戦する。残りは待機。
各参戦者には異なる首都が1セルあり、領地は首都につながるセルで構成される。

## 戦闘インターバル

［メニュー］→［征服者の関係ツリー］で、全征服者の上下関係を確認できる。独立した征服者を根として、直属の手下・手下の手下を肖像と接続線で表示する。［手下にする］では勝者を直接の上位者とし、敗者が既に持つ手下の階層は保持して配下へ組み込む。同じツリーの征服者は戦闘せず、陸路の住民移動を共有し、上位者から深さ優先で操作する。循環する上下関係は作れない。
［逃がす］ではその征服者と配下のツリーを独立させる。［電池を引き抜く］では直属の手下を元の上位者へ引き継ぎ、上位者がいなければそれぞれ独立させる。ツリー画面では操作中・操作できる・敵・その場に留まる・電池なしを見分けられる。戻るボタンまたはEscでゲームへ戻る。

自分または手下が、征服者のいる節点を勝ち取ったときは、戦闘後にその征服者の処遇を選ぶ。［手下にする］で同盟し、［手下のターン］ボタンで順に操作する。全員の移動または待機を選んだ後に、敵の行動・人口更新・戦闘をまとめて１ターン分進める。手下同士は戦わず、陸路でつながる互いの節点間で住民移動を設定できる。
［逃がす］では征服者はその節点に留まり、自動移動しない。［電池を引き抜く］ではその征服者が所有する節点を未征服（灰色）にし、住民は残す。未征服の節点は、戦闘員０人でも征服者が移動すればその所有になる。電池を抜いた征服者は行動せず、地図の電池マーカーも表示しない。
［メニュー］→［電池を引き抜いた征服者一覧］で肖像を閲覧できる。［電池を入れる］で起動すると、改めて同じ３つの処遇を選ぶ。以前の領地は自動では戻らない。現在は既存の性格が「高飛車」「人の話を聞かない」「怒っている」の征服者が手下入りを拒み、残りの２択から選ぶ。クイーンの敗北と、征服者がいる節点の占領を処遇へ接続する。敵同士の敗北した征服者は、その場に留まる扱いにする。

移動確定または待機ターンで戦闘が発生すると、次の操作ターンへ進む前に戦闘画面を表示する。戦闘がなければ通常画面のまま進む。
節点（Node）での節戦（Node Battle）と、互いに同じ辺を逆方向へ進む軍の辺戦（Edge Battle）を扱う。辺戦の生存軍だけが敵側の節点へ続き、武器残数を引き継いで節戦を行う。辺戦中に帰還先を失った軍は敗北する。全軍が退却した辺戦では双方が帰還する。
観戦は保存した各フェーズのフレームを再生するため、早送りや停止で結果は変わらない。複数の戦場は［前の戦場］［次の戦場］で選べる。操作ログにはロボット設定画面・輸送再生・継戦の状態も記録する。

## スクリーンショット

Ctrl+P（左右どちらのCtrlでも可）で、描画済みのゲーム画面をPNG保存する。
タイトル・世界作成・征服者作成・SEEDダイアログのいずれでも撮影できる。
保存先は開発実行時はプロジェクトルートの `Screenshots/`。配布版では実行ファイルの隣の `Screenshots/`。
画像サイズは現在のウィンドウの描画領域と同じ。余白の背景も含めて保存する。
ファイル名に日時と識別子を付けて上書きを防ぎ、キーを押しっぱなしにしても1回だけ保存する。
文房具UIのデモにある、Draw後のGetBackBufferDataとSaveAsPngによる保存方式を参考に実装。
保存成功後は文房具UI（StationeryUI.MonoGame 0.3.0）の共通シャッター音と0.42秒のシャッターエフェクトを再生する。演出と保存通知はPNGに含めない。音声機器が使えない場合も撮影と視覚演出は動作し、音声エラーは操作ログへ記録する。

征服者作成画面の操作ボタンと3種類のSEEDボタンは下端の1段に配置。
寸法・表面セル数・参戦人数と操作案内は中央の地星儀区画に表示する。
## 完成画像による人物抽選

imagegenで60人それぞれ6つの角度・ポーズを描いた、合計360枚の完成画像を使用する。
目・耳・眼鏡類のランタイム合成は廃止。従来のオリジナル画像と差分素材は保管する。
現在の素材は Content/Images/Portraits/sheet-01.png ～ sheet-10.png。
各シートは6列×6行で、1行が同じ人物の6パターン。1シート36枚、10シート360枚。
抽出した個別PNGは同ディレクトリーの tiles/ 以下。描画はシートの該当区画を直接読む。

目・耳・眼鏡類は人物ごとにランダムな共通特徴を指定し、各画像で性格・表情・状況をランダムに指定。
顔の角度とポーズを変え、見える目は視聴者へ向ける指定。線目・眠気・笑顔・瓶底眼鏡では目が見えない場合がある。
表情・状況は生成時のキーワードで、ゲーム内でその行動を演じる処理ではない。
manifest.json に360枚の指定を保存。prompt-01.txt ～ prompt-10.txt に実際の生成プロンプトを保管。
生成画像ではキーワードの細部が完全には一致しない場合がある。

60人から20枠を抽選するため、毎回出ない人物がいる。75％の確率で、20人全員が異なるベースになる抽選を行う。残り25％では従来の姉妹を含む抽選を行い、同じ人物は異なる画像で最大6人まで登場する。10,000 SEEDの確認では全員別ベースが7,538回（75.38％）。
同じ完成画像は同じ回で重複しない。双子から6つ子まで別々の国の色を持つ。
顔にマウスを置くと、中央に人物番号・画像番号・テーマ・表情と状況の指定・姉妹人数を表示。
人物SEEDは画像選択と国の色を再現する。31ビットの範囲を引き続き使用する。
人物生成方式を変更したため、過去の差分合成版の人物SEEDとは結果が異なる。
世界と配置の生成方式は維持。完全再現には3種類のSEEDを順番に入力する。

描画確認画像は Screenshots/PortraitReview/completed-01.png ～ completed-10.png。
## 配信向けセル数表示とバックグラウンド動作

領地が決まると、顔カード右下に国のセル数と cell を表示する。
数字は顔画像の縦幅の約1/3、cell はその半分の高さ。Comic Sans MS の丸い太字を使用し、
国境と同じ国の色で描き、暗い背景と縁取りで写真上でも読みやすくする。
領地確定前の「参戦」表示は廃止。待機人物は領地抽選後に 0 cell と表示する。

ウィンドウが非アクティブでも、抽選と地球儀の回転を更新し続ける。
クリック・キー操作はアクティブ時だけ受け付ける。SEED入力ダイアログ中の抽選停止は維持する。
## 世界征服者選択

7×5のカレンダー区画を維持し、各区画を4×4に分割した28×20（560マス）のサブグリッドを使う。
各参戦者の顔の面積は領地の割合で決める。辺の長さは floor(sqrt(496 × 国セル数 / 世界セル数))、
最小1、最大20。面積は1、4、9、16…400という平方数になる。
サブグリッドのマスはカレンダーと同じ長方形比率で、顔は縦横同じマス数を占める。
大きな顔から詰め、幾何的に収まらないときは大きな顔を一段縮小して再配置。
全参戦者が重ならず収まることを優先するため、比率の表現は近似。余りマスには画像を置かない。
領地がない待機人物はプレイヤーとして選べない。

顔へのホバーで左上へ10×10px移動し、元の位置にドロップシャドウを描く。
10pxは1920×1080の論理画面での寸法で、ウィンドウの拡縮時は他の要素と同率で拡縮する。
クリックで WorldSetup.PlayerSlot に国のスロット番号を記録し、その人物を「あなた」と表示する。
選び直すボタンで再選択できる。人物・世界・初期配置を作り直すと操作人物の指定を解除する。
プレイヤー確定後は「世界征服状況へ」ボタン、または Enter で状況画面へ進む。

## 地星儀と向きの玩具人形

世界観設定に合わせて、形状に応じた表示名を地棒儀・地盤儀・地箱儀とする。世界作成、人物・初期配置の確認、キャラ選択の各立体表示に、向きの目印となる玩具ロボットを並べる。
人形は碗を＋X側、箸を−X側に持ち、頭は＋Y、足は−Y、腹は＋Z、背は−Z。前面は顔・操作盤、背面は巻き鍵で見分ける。地星儀と共通の回転行列を使い、ドラッグ・自動回転のどちらでも向きを連動させる。人形は操作人物ではなく、絶対方向の目印。
`dotnet run --project tests/ToyUi/ToyUi.csproj` で形状名、ドラッグと自動回転の同期、正面・背面、配置確認・キャラ選択、小さいウィンドウの描画を検証する。
最後にホバーした人物の領地を国境と同じ色で全面塗りし、照明に依存しない明るさで穏やかに点滅させる。
キャラ確定後は自分の国をハイライトする。配置確認へ戻ると解除する。

## 世界征服状況

左側にはカレンダー2×2マスの肖像と金色の額縁、征服者名、政治体制（全員「独裁者」）、首都名、領地数を表示する。
右側は地球儀と同じ地形を使う6面の展開図。自国のセルが最も多い面を中央に置き、自国の色を点滅させる。
左右回転ボタンで90度ずつ回転し、矢印キーで中心面を移す。「自分の国へ」「首都の面へ」「北を上に」で表示を戻せる。セルのクリックでは中心面・向き・配置を変えない。
同じ英字が付いた辺同士は地球上でつながる。セルへのホバーで都市名と征服者名を表示する。

外周の辺や、その近くのアルファベットにカーソルを合わせると、同じ文字の辺と文字を両方黄色く強調する。つなぎ替え可能な辺または文字をクリックすると、地星上で隣接する面と、その面につながる枝を切り離し、約0.85秒かけて移動・回転させて接続する。
中心面と全体の回転は維持する。接続済みの辺と、接続後に面が重なる辺はつなぎ替え対象にしない。アニメーション中は追加の辺・セル操作を受け付けない。
セルの中心をクリックしても辺操作にならないよう、辺の判定は辺の近くと文字の矩形に限る。ズーム・パンで広げた地図でも同じ操作ができる。
通常面の北は +Y。北極面の上は +Z、南極面の上は -Z を基準とする。

地形上の面名帯は表示しない。極面の陸地は雪色、英字は離れた辺だけに表示する。
マウスホイールで地図ビュー中央を固定して0.5～64倍に拡縮し、スペース＋左ドラッグで地図を移動する。［現在地へ移動］は倍率を保って現在の節点を中央へ寄せる。
座標は角度ではなくセル単位の経番・緯番。座標の組は GeoJSON と同じ（経番,緯番）の順。
［□地星儀 □展開図］で立体と展開図の表示を切り替える。展開図には定規や辺沿いの座標を描かない。地星儀では手前のセル中心から外向きの法線を描き、法線方向に２セル分（世界座標で２）離した上空の位置へ、経番を赤系、緯番を緑系の文字として表示する。左ドラッグで回転すると法線と番号もセルに追従するが、文字は常に画面に正対し、サイズは一定。裏側の番号は隠し、文字が重なる場合や表示枠から外れる場合は間引く。文章中の座標・節点名ヒントも同じ色分けにする。
旗・電池・交通路の表示設定は地星儀でも使える。移動ボタンは地星儀／展開図の表示を保ち、交通路へ一時的に切り替える。点滅する節点をクリックして移動先を選び、確定で移動する。地星儀でもドラッグ回転して裏側の候補を探せる。確定・取消・閉じる操作で元のグリッド／交通路表示へ戻す。
［グリッド／交通路］と［地星儀／展開図］は、それぞれ一つの切替ボタンで、どこを押しても交互に切り替わる。移動先選択中にグリッドへ切り替えると、未確定の移動を取り消す。
ゲーム中の地星儀でセルをクリックすると、そのセルをビュー中央に置いた展開図へ切り替える。クリックした面を中心面とし、地星儀で見ていた面の向きに最も近い90度刻みの回転を選ぶ。拡縮をリセットし、地星儀の向きは保持する。ドラッグ回転と移動先選択は従来どおり行える。
地星儀のセルへカーソルを合わせると、クリック判定と同じセルの境界を黄色と暗い縁取りで強調する。裏面や地星儀の外側は強調しない。

操作ログは起動ごとに `Logs/operations_日時_識別子.jsonl` へUTF-8で保存する。開発時はソリューション横、配布時は実行ファイル横の `Logs` を使い、書けない場合は `%LOCALAPPDATA%/FolderVerse/Logs` へ保存する。ログはGit管理対象外。各行が一つのJSONイベントで、時差付き時刻・起動後経過時間・連番、表示画面と重なっているパネル、表示モード、クリックの実座標と1920×1080換算座標、画面サイズ、フォーカス状態、キー・ホイール、操作前後の状態・結果、３つのSEED・ターン・現在節点・選択先を記録する。ボタン押下だけでなく解放・ドラッグ（最大10回/秒）も記録する。
入力開始前と終了後を即時に書き出し、例外も記録するため、途中で失敗した場合は最後の入力開始と例外から操作を追える。表示切替は `layer_changed` または `view_changed`、非アクティブの入力は `ignored_inactive_window`、移動中にグリッドへ切り替えた場合は `movement_cancelled_for_grid` と記録する。ログ保存できない場合は画面上に案内を表示する。過去のログがない操作やフレーム間で押して離されたクリックは遡って復元できない。
`dotnet run --project tests/OperationUi/OperationUi.csproj` でログ内容・連続した表示切替・移動中のグリッド選択・非アクティブ入力・縦余白のあるウィンドウのクリック座標を検証する。
ゲーム中の地星儀の隣にも方向のロボットを配置し、地星儀と同じ向きで回転させる。［頭を上へ、腹を手前へ］は頭（＋Y）が上、腹（＋Z）が手前となる姿勢へ戻す。展開図では正面（＋Z）の面を中央にして回転を０へ戻す。
地星儀の腹・碗・背・箸の４面では、表示される各列の最上端だけ経番、各行の画面に向かって最左端だけ緯番を残す。回転後も画面上の位置で選ぶ。頭・足の面では、同じ番号が一直線に連続する場合に両端だけその番号を残す。両方の番号が省略される場合はラベル・背景・法線を表示しない。枠外や間引きで欠けた場合は残る表示セルから端を選ぶ。
頭・足の面の地形色は共通の `WorldTerrain.ColorAt(height, normal)` で決め、陸地は雪の白、山は陰影を付けた白、海は冷たい白寄りの青にする。地星儀・展開図・面のつなぎ替えアニメーションが同じ配色を使う。色だけの変更で地形判定は変わらない。
`dotnet run --project tests/GlobeUi/GlobeUi.csproj` で地星儀と展開図の切替・座標の投影と裏面非表示・ドラッグ回転・移動時の表示復帰・色分け・小さいウィンドウを検証する。
経番の起点は箸（－X）と腹（＋Z）の境目。腹側の最初の列が経番0で、腹を箸側から碗側へ進む向きを正とし、一周の後半は負になる。箸側で境目に接する列は経番－1。極面の各リングも箸・腹側の角を経番0にそろえる。緯番0は側面の中央行（偶数高さでは北側の中央行）。北が正、南が負。起点の変更は表示番号だけに作用し、セル・NodeのID、交通路や移動方向には影響しない。
極面は外周から内側へのリングごとに緯番を進め、リング内の経番を赤道の番号範囲へ割り当てる。全セルの座標は一意で、地図の回転では変わらない。
首都・ホバー都市・征服者現在地に座標を表示する。各征服者は最初は首都におり、現在地は首都とは別に保持する。
操作人物の現在地には、生存の印となる電池アイコンを点滅表示する。
敵征服者の電池は国の色で固定表示し、点滅させない。展開図のつなぎ替えアニメーション中も同じルール。

## 節点ダイアログ

展開図の節点をクリックすると、その節点のロボット０～12体を４列×３段で表示する。頭・胴・脚の構成、所有国色・番号、個体IDを確認できる。海や他国の節点も調査できる。空の節点は空枠と案内を表示する。×または Esc で閉じる。
下部のタイル型［ロボット製造工場］を押すと工場ダイアログへ切り替わる。自分と自分の配下（手下の手下を含む）の節点で操作でき、他国・上位者・中立の節点では無効。製造パーツ７種類、製造計画の適用、停止／再開、工期±を設定する。計画や工期の変更は製造の進捗をリセットし、継戦中は変更できない。×またはEsc、選択中の工場タイルを押すと節点へ戻る。製造機能は輸送計画画面から移動した。

## 征服者の移動

［移動］を開くと一時的に交通路表示へ切り替え、直接つながる移動先節点（Node）の輪を点滅させる。地図上の節点をクリックして行先を選び、［確定］で1ターンの移動を実行する。選択した節点には白い輪も表示する。一覧をクリックして選択することもできるが、選択だけでは移動しない。同じセル内・隣接セル・面をまたぐ移動と海の節点にも対応する。
確定・×・Esc・［移動］の再クリックで移動画面を閉じ、開く前のグリッド／交通路表示へ戻す。行先が未選択なら確定できない。移動画面を開いている間は待機ターンと表示モードの手動切り替えを受け付けず、拡縮・ドラッグ・展開図のつなぎ替えは引き続き使える。
同行する完成体を１体刻みで選ぶ。［全員］と［０人］も使える。組立・分解・廃棄の予約中の個体は通常の同行・増援から除外する。
［ターン → 次へ］は待機として全体ターンを進める。敵も同時に隣接節点への移動を計画し、移動できる完成体を連れる。戦場参加中のクイーンは新たに出撃できず、継戦辺も越えられない。敵の行動は配置SEEDとターン数から再現する。

生産者・残数は節点に残り、ロボットの出撃で人口は減らない。領有は旗・戦意・生存軍で決まる。征服した節点の役割異動率・移住率は0へ戻す。領地数を再計算し、首都を失っても領地があれば人口最多の自国節点があるセルを新首都にする。
自国の節点がなくなると放浪者になる。征服者は移動・待機でき、中立節点では旗上げできる。直属のロボットは征服者と一緒に移動する。
地図の大きな電池は操作人物、小さな各国色の電池は敵征服者の現在地。ターン結果は地図の下へ表示する。

## 地形経路・節点・グリッド

［グリッド / 交通路］は押すごとに切り替わる排他的な表示ボタン。旗と電池は独立して点灯・消灯できる。交通路は海・陸・山の通行経路の総称。ゲームフェーズには「キャラ選択へ戻る」ボタンを表示しない。
展開図の旗は各節点の領有国を表す。交通路表示のノード色と同じ情報で、グリッド表示でも領有国を示す目印になる。節点にカーソルを合わせると都市名・座標・地形・セル内位置・Node番号のヒントを表示する。

海港は海陸をつなぐ交通路の陸側の地点を独立した節点（Node）にする。同じ陸側地点へつながる港は一つにまとめ、通常の節点と同じ移動・領有・人口・戦闘処理を使う。海から陸へは港の節点を経由する。錨は通常のノードより大きくし、領有国の色で表示する。以前の小さい錨の目印を重ねて描かない。地星儀・展開図・つなぎ替えアニメーションで共通の錨描画を使う。

海港名は次の語をカタカナへ近似した読みと、重複しない地点番号の組（例：プエルト・123）で生成する。同じ世界SEEDと地点なら再配置しても同名。浜・海辺を意味する語も港の地名として使う。

各セルの地形は10×10。海抜0.52未満は海、0.52以上0.72未満は陸、0.72以上は山。山は壁で、一部の山には世界SEEDで決まる狭い峠がある。
辺の海・陸・山の連続区間ごとに、その区間の中央へ通過点を置く。共通の3D辺を使うため、展開図をつなぎ替えても隣接セルへの通過点は変わらない。険しい山や上陸できない海岸の通過点は閉鎖される。
交通路表示では国による地形の面塗りとセル境界線を消し、節点を国の色の丸印で示す。グリッド表示では従来の面塗りを表示する。交通路は階段状の折れ線を通行可能領域内で整理してから、滑らかな曲線で描く。境界の通過点マーカーは表示しない。セル境界への接続は両側で辺に垂直な接線を持つ3次ベジェ曲線を優先し、山の壁などで通れない場合だけ元の安全な経路を残す。描画経路の起点は節点中心とし、直接つながる節点間を描くため、節点の丸印は交通路のノードに一致する。海路は水色、陸路は黄色、山の峠はオレンジ。壁・閉鎖された地形境界を横切る短縮や曲線は採用しない。

移動は交通路で直接接続された節点へ1ターンに1回。地形の通行ポイントを節点単位にまとめ、節点境界を1回だけ越える接続を移動候補にする。途中の節点を飛び越えない。同じセル内の海・陸・山の節点間も移動でき、港でのみ乗船・上陸する。到着位置は常に節点中心で、次の移動はその節点から探索する。
現在地は「都市名（経番,緯番,南東側・海）」のように表示する。移動画面では節点の固有番号（Node）も表示する。電池の初期位置・移動後の位置は節点中心（丸印・経路ノード）にそろえる。

生成時に全世界の通行ポイントと面をまたぐ接続を検査する。つながっていない湖や島には、緩やかな海岸を優先して必要な港を追加する。港1か所の湖は行き止まりになり、別々の通行領域を接続する必要があれば複数の港を持つ。港で補えない孤立には、山をできるだけ避ける短い通路・峠を追加する。生成後の通行網が1つに接続されることを確認する。港・通路は世界SEEDから再現される。

移動画面には到着可能な節点を1件ずつ表示し、5件を超えればページを切り替える。方角は北・北北東・北東などの16方位。面をまたぐ場合は出発面へ隣接面を展開した位置で方角を計算する。同じ方角の節点も固有番号で区別できる。16は方位名の数であり、接続先節点数の上限ではない。到着した節点だけを戦闘対象にし、敵も同じ到着候補を使用する。
白い三角形は山頂の目印。港の節点は領有国の色を付けた大きな錨で示し、地図の上に凡例を表示する。
`dotnet run --project tests/NodeMovement/NodeMovement.csproj` で64世界の全節点への到達、接続の対称性、セル内・セル間移動と戦闘、敵の節点到着、再生成を検証する。
`dotnet run --project tests/NodeUi/NodeUi.csproj` で実画面の描画、フォント、ページ操作、地図での選択・確定・キャンセル、表示モード復元、座標色分け、電池の点滅、削除した戻るボタンの当たり判定を検証し、自動終了する。

同じ地形でつながるセル内の領域を正式名称「節点」、英語名 Node として管理し、各節点が国・人口・旗を持つ。陸の人口パネルはクリックした自国節点を対象にする。移住は同じ国の節点まで陸路がある場合に有効。
戦闘は到着した節点に対して行い、参加する国とロボット個体を区別する。同じセルの別節点は巻き込まれない。
一部の節点を奪ったセルは未占領（部分占拠）。各節点の色と旗、通行可能領域の面積割合を表示する。全節点が同じ国になったときだけ完全占領としてセル征服数に数え、国の色の外周を表示する。節点が一つでも残ればその国は存続する。
節点の接続は孤立・行き止まり・接続先数で表示し、16方位の方角を併記する。セルにカーソルを合わせると、海と陸など各接続パターンを表示する。

世界の天候・旱魃・風の魔法などの効果範囲はセル単位、征服者の所在・移動・戦闘は節点と経路単位とする設計。天候や魔法の効果処理は今後追加する。

各セルは世界SEEDから再現できる固有の都市名を持つ。海・沿岸・草原・丘陵の地形に合わせた語をカタカナで組み合わせる。
海セルは面をまたぐ隣接関係で最寄りの陸地都市を探し、「都市名・方角」という集合地点名を付ける。
方角はその都市の北方向を基準にする。すべて海の世界には独立した名前を付ける。
同名になる海域には追加の語を付けて区別する。征服者名は人物SEEDから再現する。

節点ダイアログ下部の［ロボット輸送計画］タイルは、敵・中立を含むどの節点でも使える。７パーツ構成ごとに隣接節点への輸送率を５％ずつ設定し、操作中の征服者の計画として保存する。他国の計画は変更しない。敵の支配地へは実際の輸送を行わず、計画は残る。領有関係が変わり輸送可能になると既存の計画を使う。×・Esc・選択中のタイルで節点へ戻る。

戦場の障害物は文字を廃止し、草地は木、岩場・砂地は岩、寒冷地は氷、海は岩礁、橋上は樽で描く。現在の地形には独立した砂漠区分がないため砂地・岩場を岩表示にする。各軍の自陣の辺は所有国色の帯と［退却］で示し、退却ルールの北・東・南・西と一致する。

節点ダイアログ下部に［ロボット廃棄計画］タイルがある。自分と配下の節点で、廃棄待ちの個体の順番だけを↑↓で変更できる。順番未指定の個体はID順に選ばれる。炉がない節点では廃棄フラグを保持して待ち、炉のある節点へ運べる。処理中は次の個体を入れず、対象を輸送・分解・出撃に使えない。継戦中は炉の進捗も停止する。

節点の個体カードの［廃棄］チェックは、自分のロボットについて変更できる（処理中・予約中は変更不可）。輸送計画は［ふつうの移送］と［廃棄としての移送］を別々に保存し、同じパーツ種類の２計画の合計を100％以内に設定する。廃棄用の移送は届いたパーツへフラグを付け、残ったパーツは元の状態を保持する。既に付いたフラグは通常輸送でも保持する。廃棄対象は到着時の自動組立をせず、炉が空いていれば到着ターンの最後にレーンへ入り、次の全体ターンから処理が進む。

［節点ダイアログ］下部の４つ目の［ロボット組み立て・分解］は、手動での再調整用の格納庫。自分と配下の節点で、頭・胴・脚を１種類ずつドラッグし、空きセルへ分解、同じ所有国で同じ廃棄フラグの別パーツへ組み立てできる。ホバー時はつかめるパーツを枠と案内で示し、ドラッグ中はパーツの絵とドロップ先を表示する。変更は即時で、全体ターンは進めない。重複・満杯・処理中・予約中・継戦中の不適切な操作は元の状態を保持する。盤外やフォーカス喪失、ドラッグ中のEscで取り消し、通常のEsc・×・選択中のタイルで節点へ戻る。

主な運用は輸送計画による自動分解・到着時の自動組み立て。応急的な再調整を維持したい節点には［自動での組み立て・分解を行わない］をチェックする。この設定は節点単位で保持され、出発時の部分輸送と到着時の自動合体を停止する。丸ごとの輸送と手動操作は続けられ、チェックを外すと以後の輸送から通常の自動処理に戻る。
